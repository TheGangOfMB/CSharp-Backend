## Из диагностики 16.10.2026

- **Unboxing в другой тип.** Думал, что `object o = 5; long l = (long)o;` даст 5 → упакованный `int` распаковывается только в `int`, иначе `InvalidCastException`; правильно `(long)(int)o` → **открыто**
- **Копирование struct.** Думал, что после `var b = a; b.X = 5;` у `a.X` тоже 5 → struct — тип значения, `b` — независимая копия, `a.X == 0` → **открыто**
- **finally после return.** Думал, что `return` в `try` пропускает `finally` → `finally` выполняется всегда (кроме падения процесса); метод вернёт значение, но сначала выполнит `finally` → **открыто**
- **async void.** Не знал, чем опасен → нельзя дождаться через `await`, исключение не ловится вызывающим `try/catch` и обычно роняет приложение; использовать `async Task`, `async void` — только для обработчиков событий → **открыто**
- **Отложенное выполнение LINQ.** Ответил верно, но с LINQ почти не работал — проверить, понимает ли причину, а не угадал → **открыто**
- **Git.** `reset --hard` vs `revert` не знает: reset переписывает историю и стирает изменения, revert создаёт новый коммит, отменяющий старый → **частично**: 18.10 выбрал revert и объяснил про расхождение историй, но через наводящий вопрос. Проверить на повторении.

## Занятие 18.10.2026

- **Git: modified.** Думал, что `modified` = «файл сохранён в Git» → наоборот: файл изменён на диске относительно последнего коммита и эти изменения ещё **не** сохранены → **открыто**
- **Git: staged.** Считал, что после `git add` изменения уже «сохранены в Git» → `add` только кладёт в staging, сохраняет `commit` → **открыто**
- **Тип vs экземпляр.** Объявлял поля `int a, b;` внутри struct вместо переменных-экземпляров; задавал значение в описании типа. Путает описание типа (чертёж) и создание объекта → **открыто, важно**
- **Ссылочный тип, вывод.** Верно сказал «копируется ссылка», но предсказал `c=100, d=999` → если две ссылки на один объект, изменение через одну видно через другую → исправил сам после наводящего вопроса → **открыто**
- **`namespace std`.** Дважды написал C++-шное пространство имён, после замечания не исправил → **открыто**
- **Свойство-struct (CS1612).** Не смог объяснить, почему `transform.position.x = 5` не компилируется → геттер возвращает копию struct, изменение копии потерялось бы; в бэкенде то же с `list[0].Amount = 5` для `List<struct>` → **открыто**
- **Переменная vs объект.** В конспекте писал «ссылка на память переменной `a`» и `a = 50 → b = 50` для class → ссылка указывает на **объект**; `a = new ...` меняет только переменную `a`, `b` остаётся на старом объекте. Проверено экспериментом `e`/`f`, прогноз дал верно → **частично, проверить на повторении** (вопрос: `param = new ...` внутри метода)
- **`git add .` из подпапки.** Стоял в `lessons/`, закоммитил 1 файл из 5 → `.` = текущая папка; команды Git выполнять из корня → **открыто**
- **«Исправил», но не сохранил / не сделал.** Дважды говорил «исправил», а заголовок `Struct:` оставался, конспект не менялся, `add` без `commit`. Одинаковые сообщения коммитов → перед «готово» проверять `git status` / вывод программы → **следить**
- **Неточные формулировки.** «Не готовы к изменению» вместо «не добавлены в индекс». На собесе за размытые формулировки снимают баллы → следить

## Занятие 19.10.2026 (вторая часть)

- **Git: staged + modified одного файла.** Сказал, что `git status` покажет просто `modified` и закоммитится «Program.cs» → файл виден дважды: в индексе версия на момент `git add`, в рабочей папке — новая; `commit` берёт **только индекс** → **открыто**
- **«add = сохраняем».** Снова: «мы сохраняем файл» про `git add` → `add` добавляет в индекс, сохраняет `commit` → **открыто, повтор**
- **Метод без `ref`: изменение объекта vs переприсваивание.** На `o.Amount = 0; o = new ...` ответил 777, потом 100 → правильно 0: через ссылку меняется общий объект, `o = new` меняет только локальную переменную. Держит в голове только одно из двух правил → **открыто, важно**
- **CS1612, объяснение.** Код «достать → изменить → положить» написал верно, но объяснение «присваиваем временное значение» и «массив работает, потому что ссылочный» → индексатор `List` — метод `get`, возвращает копию; элемент массива — переменная, прямой доступ; List тоже ссылочный, это не причина → **частично**
- **Индексатор.** Забыл, что это → свойство с параметром `this[int i] { get; set; }` → **открыто**
- **«new → куча» для struct.** Сказал, что `Money local = new Money()` лежит в куче, а `local` — ссылка → для struct `new` только вызывает конструктор, память не выделяется в куче; локальная struct — в стеке, хранит само значение → **частично** (после подсказки ответил верно)
- **Поле-struct «отдельный объект в куче».** → поле-struct встроено inline в память объекта-владельца, своей ссылки и заголовка нет → **открыто**
- **`ref` для ссылочного типа.** Сначала ответил как без `ref` (100) → с `ref` параметр — псевдоним переменной вызывающего, `o = new` перенаправляет и её → 777 → **частично** (исправил после наводящего вопроса)
